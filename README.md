# 双轨字幕流水线演示

本地两套字幕来源（`samples/dialogue.srt` 对白轨、`samples/sfx.srt` 音效轨），演示：

- **采集端**：逐段保留全部版本历史；修订可以是「只替换一段」，也可以是「把一段从一轨挪到另一轨」。
- **合并端**：合并成播放版本前检查时间范围（`start < end`、同轨不重叠），非法即拒绝。
- **播放器**：只能读同一版的两轨（结构上两轨来自同一版本对象；API 显式拒绝混版请求）。
- **分发**：可选「整片分发」（整包原子替换）或「段级补丁」（只传变化的分段，暂存区 + 校验和两段式提交）。
- **中断恢复**：补丁应用中途打断时，暂存区对播放器不可见，旧字幕仍可读；可回滚恢复，也可续传/重放到完成。

## 运行

```bash
node server.js          # 读取 PORT（默认 3000），绑定 127.0.0.1
# 打开 http://127.0.0.1:3000
```

页面上按顺序点三个按钮即可核对前后结果：

1. **导入双轨字幕** — 解析两个本地 .srt，合并出 E1 并整片分发到播放端。
2. **打断片段修补并恢复** — 修订（替换 d2、修正非法修订 d3、把 d4 挪到音效轨）→ 合并出 E2 → 段级补丁分发，中途打断 → 旧版本仍可读 → 回滚恢复 → 重放提交到 E2。分发方式下拉框可改选「整片分发」。
3. **对比播放版本** — 并排展示 E1 / E2 两版的双轨内容与分段级差异。

业务结果区是 `<section id="result" data-evidence-result="…">`，属性值随操作变化，格式为
`操作:ok|error:操作前播放版本>操作后播放版本`（如 `revise:ok:E1>E2`），便于自动化核对操作前后内容。

## 测试

```bash
node --test
```

`test/core.test.js` 覆盖域逻辑（解析、逐段版本、合并校验、播放器一致性、补丁中断/恢复/篡改等正常与异常路径）；
`test/http.test.js` 覆盖 HTTP 层（页面属性、完整流程、错误码）。

## 结构

```
server.js        HTTP 入口（node:http，PORT + 127.0.0.1）
lib/srt.js       SRT 解析
lib/core.js      采集端 / 合并端 / 版本库 / 播放器 / 分发与补丁应用
lib/app.js       三个页面场景的编排
public/index.html  单页演示（原生 fetch，无外部依赖）
samples/*.srt    本地样例（对白轨、音效轨）
test/*.test.js   node --test 用例
```
